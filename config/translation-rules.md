# 翻訳・ローカライズ方針

この文書は、Livewire公式ドキュメントを日本語化する際のSSOTです。

## 基本方針

- 原文の意味と技術的正確性を最優先する。
- 日本語として不自然な直訳を避け、日本の開発者に伝わりやすくする。
- 原文にない仕様、挙動、推奨事項を追加しない。
- 既存の日本語訳がある場合は表現を尊重する。
- upstream変更時は全文を再翻訳せず、変更箇所だけを更新する。

## 原則として変更しないもの

- Livewire API、Laravel API
- PHPクラス名、メソッド名、プロパティ名、PHP Attributes
- `wire:*` ディレクティブ
- Artisan、Composer、npmコマンド
- ファイルパス、URL
- 技術的な意味と処理フロー

## ローカライズしてよいもの

理解しやすくなる場合、サンプルコード内を含めて次を日本向けに変更してよい。

- 表示用文字列、投稿タイトル、投稿本文
- 人名、住所、商品名、日付、金額
- その他、技術的な意味に影響しない英語圏固有のサンプルデータ

## Markdownとコード

原文の構造を可能な限り維持する。見出し、リスト、コードブロック、Callout、リンク、アンカーを壊さない。コードは実行可能な構造を維持し、翻訳するのは表示用文字列などに限る。

## upstream更新時の手順

1. `.upstream-version` から現在のupstreamまでの差分を確認する。
2. 変更箇所に対応する日本語訳を確認する。
3. 変更された内容だけを反映する。
4. 既存の日本向けローカライズを可能な限り維持する。
5. 原文差分と日本語版をレビューする。

## レビュー観点

- 原文の意味が欠落していないか。
- 原文にない意味を追加していないか。
- 技術的意味が変わっていないか。
- 日本語が自然で、用語が統一されているか。
- ローカライズが過剰でないか。
- Markdown、コード、リンクが壊れていないか。
