# Web UIデザインレビュー原則 v0.1

## 使い方

これは採点表ではない。数値や規則は、同種要素の比較と意味の伝達を説明するために使う。原則に合わないことだけを理由に指摘しない。

## 1. 観測可能な規則

- **spacing**: 同じ役割の要素に反復する値があるか、値の種類が増えすぎていないかを見る。8px基準は候補であり必須条件ではない。
- **alignment / grid**: 左端、中心線、カード幅、列間隔、見出しと本文の開始位置を比較する。意図的な独立領域なら基準線が違っても直ちに問題とはしない。
- **typography**: サイズだけでなく、和文の折返し、行長、line-height、見出し粒度、強調の数を一緒に見る。
- **color / contrast**: foreground/backgroundのコントラスト、彩度の競合、リンク・ボタン・状態表示の識別性を見る。WCAGの数値は必要な最低条件で、視覚階層の十分条件ではない。
- **container / responsive**: desktopの余白、本文の行長、mobileの横スクロール、折返し、タップ領域、表示順の変化を確認する。
- **実距離**: marginやpaddingの宣言値ではなく、隣接要素のbounding boxから視覚的な境界間の距離を測る。負値やゼロは重なり・内包・line boxの影響を確認し、機械的に問題としない。
- **spacing rhythm**: 近い距離が同一グループ、中距離が同一セクション内の階層、遠い距離がセクション分離として知覚される。距離の順序がDOMや意味上の関係と逆転すると、視覚構造が不安定になる。

## 2. 関係性からの判断

- 近い要素は関連して見える。グループ内の余白を小さく、グループ間を大きくすると構造を伝えやすい。
- 余白、サイズ、色、位置、線、太さの変化が同じ方向を指すと階層が明確になる。見出しだけ大きくしても周囲の余白が同じなら階層が弱いことがある。
- 同種コンポーネントは、役割が同じなら寸法・余白・タイトル粒度・文章量の差を説明できる状態が望ましい。カードの内容量が大きく違うなら、CSSで高さを揃える前に情報設計を疑う。
- 空白は不足だけでなく過剰も問題になる。コンテンツ量に対してカードやヒーローが大きすぎると、意味のない重さやテンプレート感が出る。
- 連続する距離のリズムも見る。例えば、見出しと説明の距離より説明と次セクションの距離が小さい場合、別グループが近く見える。逆に、同一グループ内の距離が大きく、セクション間との差が小さい場合は、まとまりが弱く見える。

## 3. 文脈依存のヒューリスティック

- headerとmainの左端が異なっても、headerが独立した領域として明確で、ナビゲーションの探索性を損なわなければ問題とは限らない。
- 技術ドキュメント、ダッシュボード、ブランドサイトでは適切な密度とCTAの強さが異なる。ページの主要目的を先に仮定する。
- 「AI生成っぽい」は、無意味なカードの反復、内容量と容器の不均衡、装飾の過剰、全体の均一化、見出しの粒度不一致など観測可能な兆候へ分解する。
- ヒューリスティックは、代替解釈と確信度を併記する。好みだけで「悪い」と言わず、どのユーザー行動・理解に影響するかを示す。
- 文字階層はサイズの種類数ではなく、知覚できる段階数として評価する。16px/18px/20pxのような近似値にweightやcolorの差が重なると、数値上は階層があっても日本語画面ではノイズになり得る。
- 文字階層は少なければよいわけではない。本文、補助説明、見出し、主要CTAなどの役割差が、サイズ・weight・line-height・colorの組み合わせで一貫して伝わるかを確認する。
